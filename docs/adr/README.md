# 架构决策记录（ADR）

## 编号规则

**编号一经分配即冻结，不重排、不复用、不回填。** 仓库内有 350+ 个文件（代码注释与文档正文）按编号引用 ADR，重编号会让这些引用全部失效。

由此带来两种看起来像"错误"、但实际是刻意保留的现象：

### 1. 编号空洞

以下编号在本仓库中不存在——它们记录的是服务端决策，随仓库拆分迁到了 `astravia-serv`：

| 编号 | 主题 |
| --- | --- |
| 0016 | Astravia Go 窗口配额服务 |
| 0017 | 固定槽位配额窗口 |
| 0019 | 技能管理字段以 DB 为真相源 |
| 0038 | 收敛为单一 Astravia Go，移除 Zen |
| 0039 | 全局信用基座与倍率定价 |
| 0051 | 订阅价格由支付平台持有 |
| 0052 | 双权益来源与不可变窗口锚点 |
| 0056 | 图像生成经网关按积分计量 |

### 2. 编号重复

以下编号各对应多个不同主题的文件，是并行开发时的历史产物，同样不做修正：

`0021` `0057` `0060` `0066` `0068` `0069` `0079` `0105` `0120` `0124` `0125` `0127` `0130` `0131` `0138` `0140`

其中 `0079` 有三个文件，其余各两个。引用这些编号时请连同标题一起写，避免歧义。

这两张清单由 `scripts/quality/check-adr-numbering.mjs` 机械核对：`docs/adr/` 下出现新的重号却没有登记、登记了实际并不重号的编号、「其中 `0079` 有三个文件」这句的文件数与实际不符、或「编号空洞」里出现了真实文件，守卫都会失败。

## 新增 ADR

取当前最大编号 +1。确认 `docs/adr/` 与上表的空洞编号都未占用该号。
